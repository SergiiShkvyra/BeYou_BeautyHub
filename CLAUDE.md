## Project overview

BeYou BeautyHub is a static marketing/booking site for a lash & brow beauty studio, built with Vite + React + TypeScript + Tailwind CSS. It is a single-page site (no router) that auto-deploys to GitHub Pages at www.beyoubeautyhub.com (see `CNAME`).

## Commands

- `npm run dev` — start the Vite dev server (port 5173, fixed via `vite.config.ts`)
- `npm run build` — production build to `dist/`
- `npm run preview` — preview the production build locally
- `npm run lint` — run ESLint (flat config in `eslint.config.js`, TypeScript + react-hooks + react-refresh rules)

There is no test runner configured in this repo (no test script, no test files).

## Deployment

Pushing to `main` triggers `.github/workflows/deploy.yml`, which runs `npm ci && npm run build` and publishes `dist/` to GitHub Pages. There is no staging environment — merging to `main` ships to production.

## Architecture

- `src/App.tsx` composes the entire page as a fixed sequence of section components, each an `id`-anchored `<section>` for anchor-link navigation: `Header → Hero → Services → About → Gallery → Testimonials → Contact → Footer`. There is no router and no shared state/context — each component in `src/components/` is self-contained with its own local state.
- `src/components/Header.tsx` is fixed-position and computes its own height in `App.tsx` (via `useEffect` + `document.body.style.paddingTop`) so content isn't hidden underneath it. It contains an aggressive `setInterval`/event-listener-based "force visibility" workaround to fight mobile browser rendering quirks — this is intentional, not dead code, even though it looks unusual.
- Navigation between sections uses `element.scrollIntoView()` by DOM id (e.g. `scrollToSection('services')`), not React Router.
- `src/utils/interactions.ts` centralizes `scrollToSection`, `handlePhoneClick`, and `copyEmailToClipboard` — call these instead of re-inlining them; they were previously copy-pasted verbatim across Header/Contact/Footer/Hero.
- The location/navigation-app picker modal (Google/Apple/Waze) is still duplicated separately in `Header.tsx` (desktop + mobile), `Contact.tsx`, and `Footer.tsx` via raw `document.createElement`/`innerHTML` — deliberately NOT deduped, because each instance already renders with different padding/gap/hover colors, so unifying them would change the UI. Match the established raw-DOM pattern if you touch one, but don't merge them.
- `Contact.tsx` submits the booking form client-side via EmailJS (`@emailjs/browser`), with service/template/public keys inlined directly in the component.
- `supabase/functions/send-contact-email/index.ts` is a Deno-based Supabase Edge Function that sends contact-form emails via the Resend API. It currently appears unused by the frontend (which calls EmailJS directly) — check before assuming it's live.
- Static assets (gallery photos, testimonial headshots, logo) live under `public/images/...` and are referenced by absolute path (e.g. `/images/gallery/...`).
- Brand colors (`olive` #505e47, `warm` #dbd6b2, plus redesign additions `olive-deep`, `olive-ink`, `cream`, `cream-soft`), the display/sans font stacks, and the `flash`/`marquee` keyframes are defined as Tailwind theme extensions in `tailwind.config.js` — use these tokens rather than hardcoding hex values in new styles.
- `tailwind.config.js` sets `important: true` globally, so Tailwind utility classes always win over inline/other CSS specificity — keep this in mind when debugging styling conflicts.
- The 2026 redesign (branch `redesign`) rewrote `index.css` into a lean design system: the old "ULTIMATE NUCLEAR OPTION" header CSS block and the global `transform: translateZ(0)/none !important` rules are GONE — they would have overridden GSAP's inline transforms. Do not reintroduce broad `!important` transform/visibility rules; the header's JS force-visible loop in `Header.tsx` (still present) plus one scoped `header { position: fixed; ... }` rule is the whole mechanism now.
- Scroll/entrance animations use GSAP + ScrollTrigger via `src/lib/useReveal.ts` (`useReveal` hook + `revealChildren`, elements tagged `data-reveal`). Reveals animate `opacity`/transform only — never `autoAlpha`/`visibility`, so unrevealed content stays visible to tests and assistive tech. All motion is skipped under `prefers-reduced-motion`.
- `src/components/Header.tsx`'s nav bar (Home/Services/About/Gallery/Contact) collapses independently of the top contact-bar/logo row on scroll: it lives in its own wrapper outside the collapsible container so it stays pinned at the top once the section above hides. The collapse/expand is driven by `isTopSectionCollapsed` state (scroll-direction threshold in the scroll handler) animating `max-height`/`opacity`, not `transform` — this project's CSS doesn't currently block `transform`, but height/opacity was chosen to be robust either way.
- `html, body` in `index.css` use `min-height: 100%` (not `height: 100%`) — this is required for `window.scrollY`/`scroll` events to fire at all; with a hard `height: 100%`, `body` becomes its own internally-scrolling box and the window never reports scroll position, silently breaking any feature (existing or new) that depends on scroll position/direction.
- The site shows a sparkle glyph over plain content (`src/components/SparkleCursor.tsx`, mounted last in `App.tsx` so it paints above the header's z-index-2147483647 stacking context via DOM-order tie-break) but the STANDARD native cursor (pointer/text/etc.) over anything interactive — buttons, links, inputs, `cursor-pointer`-tagged custom elements. This relies on `cursor` being an inherited CSS property: `index.css`'s `.no-native-cursor { cursor: none; }` (plain, no `!important`, no `*` wildcard) sets the baseline on `<html>`, and it's exactly the elements that DON'T already declare their own `cursor` that inherit it — every native interactive element already does (Tailwind Preflight puts `cursor: pointer` on `button`/`[role=button]`, the UA stylesheet does the same for links and `auto` for text inputs), so they're simply never affected. `SparkleCursor.tsx` mirrors this by reading each hovered element's own `getComputedStyle(...).cursor` (only on target-change, not every pointermove, since it forces a style recalc) and hiding itself whenever that value isn't `'none'` — so the JS visibility check and the CSS rule can never drift out of sync with each other. (An earlier version fought a `!important`-vs-`!important` specificity war with Tailwind's `.cursor-pointer` utility using a `*` wildcard selector — unnecessary once you rely on inheritance instead of forcing an explicit value onto every element.) `.no-native-cursor` is toggled by `(pointer: fine)`, but that's a device-level check — a hybrid touchscreen laptop still matches it while the user is actively touching. So `onMove` ALSO bails immediately on any `e.pointerType !== 'mouse'` (touch/pen), rather than moving/showing the glyph and hiding it again — the latter was visible as a glitch/flash under a fingertip on touch devices.
- The footer logo (`src/components/MedalLogo.tsx`, desktop + mobile copies) spins (`src/lib/logoSpin.ts`, wired in `Footer.tsx`) as a real 3D medal: `src/lib/medal3d.ts` traces the logo PNG's alpha into outlines at runtime and extrudes them with three.js — solid side walls on every stroke, see-through open line-art, mirrored from behind — drawn on a `<canvas>` that overhangs the `<img>` by 10% and is shown ONLY during a spin. `src/lib/medalView.ts` dynamic-imports and builds it once the logo is within ~1500px of the viewport (displayed copy only); until then, without WebGL, or after a lost context, `logoSpin` falls back to the plain CSS rotation of the logo, so a spin is never skipped. The swap must stay invisible: the canvas maps the z = 0 plane 1:1 onto the `<img>`, perspective fades in/out with the glint envelope (none at 0°, where a near camera would already show inner walls), and the `<img>`/canvas crossfade over the spin's first/last ~3%. Because the logo is traced at runtime, replacing `logoPSD-2.png` updates the 3D medal automatically.

## Learned Rules

- Before running any local command (`npm run build`/`lint`/`dev`) during a cleanup task, state up front that it's local-only and doesn't push/deploy — this user tracks GitHub Pages auto-deploy-on-push-to-main closely and will stop you to check.
- When flagging a bug found in unfamiliar code, trace the actual async control flow (setTimeout callbacks, event listeners registered inside a try/catch) before describing its effect — an initial read can look like it breaks a visible feature when it actually just leaks a listener/logs a console error, and getting this wrong requires a correction.
- When two code blocks look like copy-pasted duplicates, diff them byte-for-byte before merging — this codebase's four "identical-looking" navigation-modal blocks actually differ in padding/gap/colors, so a blind merge would have changed the UI despite the surface-level similarity.
- When a Tailwind-styled element's `getBoundingClientRect()` reports an impossible size (e.g. every sibling reporting the exact same full-viewport width/position), suspect a bare class selector elsewhere in the CSS hijacking that class name — bisect by testing the element's className in isolated increments (strip to bare minimum, add classes back one group at a time) rather than guessing from the Tailwind classes alone; that's what surfaced the `.bg-warm` nuclear-selector collision in this codebase.
- Don't assume a plain-language color name like `bg-warm`/`bg-olive` is safe to reuse on a new element just because it's a normal Tailwind utility — grep `index.css` for the literal class string first. (The redesign removed the known `.bg-warm` bare-selector hijack, but the habit stands: this codebase has been bitten before.)
- When asserting scroll positions in tests, remember `index.css` sets `scroll-padding-top` (140px since the redesign; 180px before), so `scrollIntoView` deliberately rests every section that far below the viewport top — a "section top ≈ 0" assertion will always fail.
- The header's force-visible code pins the header at z-index 2147483647, ABOVE the navigation modals (z-index 99999) — clicks near the top of the viewport hit the header even when a "full-screen" overlay is open, so in tests click overlays near the bottom of the viewport.
- The header top-bar collapse animates `max-height`/`opacity` with `overflow: hidden`, so Playwright still reports the clipped children as visible — assert the collapsible wrapper's bounding-box height, not child-element visibility.
- The header's mobile location button reads "Arlington, VA" on screen but its `aria-label` ("Open BeYou BeautyHub location…") overrides that as the accessible name — locate it by aria-label, not visible text.
- There is now a local-only QA framework (Playwright E2E/visual/a11y + Vitest unit; see `tests/README.md` and the `test:*` npm scripts); it never pushes or deploys, EmailJS is network-intercepted so tests never send real emails, and visual baselines in `tests/visual/__screenshots__/` are machine-specific.
- The Playwright suite runs with `reducedMotion: 'reduce'` because the site skips GSAP animations under that preference — without it, a click that auto-scrolls to an element can race its scroll-triggered entrance tween (the element moves mid-click and the click misses; this actually flaked once on Firefox before the setting was added).
- Phones held in landscape are ≥768px wide and therefore hit Tailwind's `md:` breakpoint while keeping a ≤500px-tall viewport — any `md:`-scoped visual change near the header/hero, and any full-viewport overlay laid out as a vertical stack (like the intro), must also be checked at a landscape-phone viewport (e.g. 844×390); orientation-specific fixes go in a `@media (orientation: landscape) and (max-height: 500px)` block (mirrored in JS via `matchMedia` when GSAP sets inline positions) rather than touching the portrait or desktop styles.
- CLAUDE.md's "don't merge/dedupe the 4 navigation-modal instances" instruction is about not extracting a shared component — it doesn't mean their per-instance padding/gap/colors are sacred; when the user explicitly asks for one consistent new visual design applied to all 3 address links, apply the same style values independently inside each raw-DOM block (still 4 separate edits, still no shared helper), rather than treating the old incidental per-instance drift as something to preserve.
- Playwright `locator.click()` on the Header's location buttons and the Contact/Footer "Salons by JC..." address buttons frequently times out with "element intercepts pointer events" / "outside of viewport" against the fixed nav — this is the header's collapse animation/force-visible loop fighting Playwright's actionability retries, not a real click-target bug; use `locator.dispatchEvent('click')` to test these specific buttons instead of `.click()`.
- Pasted Originkit/DesignPass.dev components (e.g. `RoundCarousel.tsx`, `GlitterCursor.tsx`) fail this repo's ESLint out of the box in two predictable ways: their internal render function is named with a leading double-underscore (e.g. `__OriginkitBase_Foo`), which breaks `react-hooks/rules-of-hooks`'s PascalCase-component detection and must be renamed to a plain PascalCase identifier; and they lean on `any` in a few spots (event-target casts, CSS custom-property values, dynamic tag names) that this repo's `@typescript-eslint/no-explicit-any` rejects — fix with a real type (`React.ElementType` for a dynamic tag, `as React.CSSProperties` wrapping the whole style object rather than one field, a proper interface for a duck-typed API) rather than leaving the any's in place or blanket-disabling the rule.
- Installing a new npm dependency (e.g. `three`) while the Vite dev server is already running leaves its pre-bundled dep cache stale — the page loads blank with a `504 (Outdated Optimize Dep)` console error that a plain browser reload does NOT clear. Fix: stop the dev server, delete `node_modules/.vite`, and restart `npm run dev`; only then does the new dependency actually load.
- `App.tsx` mounts a site-wide `GlitterCursor` (`src/components/GlitterCursor.tsx`, a pasted Originkit/three.js particle-trail component, needs both `three` and `@types/three` since the package ships no types of its own) as a `fixed inset-0 pointer-events-none` wrapper — non-interactive by design (both the wrapper and the component's own canvas are `pointer-events: none`) and self-disables under `(max-width: 768px)`. It's mounted AFTER `Header`/`IntroOverlay` in the DOM and shares their `z-index: 2147483647` (the header's force-visible z-index, `.intro-overlay`'s is only 100000) — an earlier version used `z-50`, which put the WebGL canvas visually BEHIND both, so it rendered but was invisible during the intro and whenever the pointer was over the header bar; equal z-index ties resolve by DOM order, so later-in-DOM wins. `SparkleCursor` is mounted last of all, same z-index, so it stays visually on top of the trail.
- `RoundCarousel.tsx`'s outer wrapper (`overflow: visible`) intentionally lets rotated side cards paint well outside its own layout box — but `getBoundingClientRect()` on that wrapper only reflects the LAYOUT box, not that paint overflow, since CSS `transform` never affects ancestor layout size. And `touch-action`/pointer handlers placed on that wrapper apply to every descendant that visually spills out of it too, since a touch anywhere in the DOM subtree bubbles up to them regardless of where it paints — which is why touching a spilled-out side card used to hijack page scroll on mobile even though it looked like it was touching empty space beside the carousel. Fixed by splitting into two layers: the 3D scene (all card faces) gets `pointer-events: none` so it's never hit-tested, and a separate, precisely `imageWidth`×`imageHeight`-sized, absolutely-centered "hit zone" sibling carries `pointer-events: auto` + `touch-action: none` + the actual drag handlers — so spin-vs-scroll is scoped to exactly the visible front card, not the wrapper's nominal (and visually misleading) box.
- `GlitterCursor.tsx` and `SparkleCursor.tsx` are both mouse-only now: `onMove` in each bails immediately on any `e.pointerType !== "mouse"`. This came after two rounds of touch-related bugs on the same root cause — GlitterCursor's trail interpolates from the PREVIOUS pointer position on every `pointermove`, which is correct for a mouse's physically-continuous motion but meant `prevX`/`prevY` used to persist across entirely separate touch contacts (tapping button A, then later tapping unrelated distant button B, drew one long streak connecting the two), and even after that was patched by resetting on `pointerdown`, real touch input still drove the trail/cursor at all — which is what "glitter/cursor glitches under fingertips" turned into. The device-level `(pointer: fine)` media query (used to toggle `.no-native-cursor` in index.css, and previously to gate GlitterCursor's render loop by viewport width via a NOW-REMOVED `MOBILE_QUERY`/`HIDE_ON_MOBILE`) is NOT sufficient on its own for this: a hybrid touchscreen device still matches `(pointer: fine)` while the current interaction is a touch, and viewport width doesn't track pointer capability at all (a narrow desktop window with a real mouse, or a wide touchscreen tablet, both got it backwards). Per-event `e.pointerType` filtering is the only thing that's actually correct here — GlitterCursor's render-loop gate was changed from `MOBILE_QUERY` (`max-width: 768px`) to `FINE_POINTER_QUERY` (`pointer: fine`) to match. Side effect worth knowing when testing mouse behavior here: the shader sizes points by motion distance (`gl_PointSize` maxes out at a ~0.5px floor when the drag distance is near zero), so a stationary click renders next to nothing — that's correct/by-design, not a bug; only actual mouse movement produces a visible trail.
- Before telling the user a text/spelling change will be visible on the page, check the rendering element's classes for CSS text transforms (e.g. `Marquee.tsx` renders items `uppercase`, so capitalization fixes there are invisible) — otherwise you'll overstate what actually changes on screen.
- Service names in `Services.tsx` and Fresha's own service names are edited independently and already differ (Fresha shows "Lash Lift& Tint" for the site's "Lash Lift + Tint"), so when renaming a service, update the site-title strings in `Marquee.tsx`/`tests/e2e/services.spec.ts`/`tests/live/fresha-links.spec.ts` but never assume the live Fresha test can match on the site title — use its per-service `freshaName` override and confirm with `npm run test:links`.
- Tests that need real animations must opt in with `test.use({ contextOptions: { reducedMotion: 'no-preference' } })` (see `tests/e2e/effects.spec.ts`), and then the first-visit intro overlay is live and swallows every click — get past it with that file's `skipIntro` helper, which retries clicks because the skip listener only mounts a beat after the starting click (a fixed two-click sequence flaked on WebKit).
- Every Playwright `test.describe` must carry a suite tag (`{ tag: '@smoke' | '@critical' | '@extended' }`) — `npm test` runs everything NOT tagged `@extended` across all 5 browser projects, so an untagged slow test silently lands in the fast suite and an untagged group is skipped by every single-suite command; the user chose which areas are critical (booking/Fresha, contact/maps, navigation, social links), so ask before moving a group between tiers.
- Stopping a backgrounded `npx vite preview` task kills only the npx wrapper — the vite node process keeps listening on port 4173 and keeps serving the OLD build (and Playwright's `reuseExistingServer: true` will silently test that stale build too); after a preview session, find the PID listening on 4173 and stop it explicitly.
- Playwright's WebKit on this Windows machine does not render CSS 3D (`transform-style: preserve-3d` flattens — the gallery carousel renders flat there), so a flat 3D effect in the `webkit` project is NOT a site bug; judge 3D work in Chromium/Firefox and ask the user to confirm on a real iPhone/Safari.
- Never fake 3D thickness with a stack of thin parallel copies of a shape — near edge-on they separate into visibly distinct layers, and the user rejected that look on the footer logo spin twice (even when asking to get the "3D inner part" back, they clarified "I don't want it to be layered again"). For a simple outline, CSS strips standing perpendicular to the faces work (with `backface-visibility: hidden` on every surface whose inside should never be seen, or Chrome mis-sorts touching perpendicular planes); for a whole line drawing with curves and holes that doesn't scale, which is why the footer medal is a real three.js extrusion (`src/lib/medal3d.ts`).
- When a 3D spin pivots behind the element's own plane (z transform-origin), take the perspective from the PARENT's CSS `perspective`, not `perspective()` in the element's transform — the transform function puts the 'screen' at the pivot, which visibly resizes the resting face by ~1px the moment the spin starts/ends; also, GSAP applies a z `transformOrigin` by folding it into `translate3d`, so the computed transform-origin showing only x/y is expected, not a bug.
